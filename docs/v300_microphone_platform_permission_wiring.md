## Purpose

RT-2c connects the DRC-owned microphone permission contract from RT-2b to a
narrow `permission_handler` adapter and declares the minimum Android/iOS
microphone permission metadata. It does not open a microphone, capture audio,
change the voice-input UI, upload audio, or run STT.

The plugin gateway is deliberately not instantiated from `main.dart` or
`HomeScreen`. A later UI checkpoint must invoke `requestPermission()` only from
an explicit user action.

## Dependency decision

RT-2c pins:

```text
permission_handler: 12.0.3
```

The package supports Android and iOS permission status/request APIs. The current
app's Dart SDK 3.11.5 satisfies the package's Dart 3.5 minimum. The package
requires Android compile SDK 35 or newer; the project continues to use Flutter's
current `compileSdk` value rather than hard-coding a separate number.

`app/pubspec.lock` is intentionally regenerated by the operator with
`flutter pub get` on the actual Flutter 3.41.7 environment. The resolved package
set includes `permission_handler_windows`, so Flutter also regenerates
`app/windows/flutter/generated_plugin_registrant.cc` and
`app/windows/flutter/generated_plugins.cmake`. RT-2c does not enable the DRC
gateway on Windows; the generated files only register the transitive desktop
plugin and are accepted after exact marker review. All three generated/resolved
files are committed with RT-2c after the package set is known.

## App-owned adapter boundary

New implementation:

```text
PermissionHandlerMicrophoneDriver
DefaultPermissionHandlerMicrophoneDriver
PermissionHandlerMicrophonePermissionGateway
```

The gateway implements the existing app-owned interface:

```text
MicrophonePermissionGateway.checkPermission()
MicrophonePermissionGateway.requestPermission()
MicrophonePermissionGateway.openAppSettings()
```

The default driver is the only RT-2c code that calls:

```text
Permission.microphone.status
Permission.microphone.request()
openAppSettings()
```

No capture API is present.

## Platform support policy

RT-2c enables the real permission gateway only for:

```text
Android
iOS
```

Web, Windows, Linux, macOS, and Fuchsia fail closed as
`MicrophonePermissionStatus.unsupported` without calling the plugin driver.
This keeps browser/desktop capture decisions outside this mobile permission
checkpoint.

## Status mapping

```text
permission_handler denied             -> DRC denied
permission_handler granted            -> DRC granted
permission_handler restricted         -> DRC restricted
permission_handler permanentlyDenied  -> DRC permanentlyDenied
permission_handler limited            -> DRC failed (unexpected for microphone)
permission_handler provisional        -> DRC failed (unexpected for microphone)
MissingPluginException                -> DRC unsupported
UnsupportedError                      -> DRC unsupported
other exception                       -> DRC failed
```

Raw exception text is not copied into public metadata. Public metadata records
only safe fields such as gateway, permission, platform, plugin status, whether a
permission request was attempted, whether settings opened, and fixed false
markers for microphone access/audio capture.

## Android declaration

`app/android/app/src/main/AndroidManifest.xml` adds only:

```xml
<uses-permission android:name="android.permission.RECORD_AUDIO" />
```

Declaring this permission does not request it at application startup. The native
permission dialog is shown only when a later explicit user action reaches
`requestPermission()`.

## iOS declaration

`app/ios/Runner/Info.plist` adds:

```xml
<key>NSMicrophoneUsageDescription</key>
<string>音声入力ボタンを操作したときに、話した内容を入力するためマイクを使用します。</string>
```

The checked-in project currently has no CocoaPods `Podfile`. RT-2c does not
claim which native package-integration path a later macOS build will resolve. It
statically validates the usage-description key on Windows; actual iOS plugin
linking and runtime permission behavior remain macOS operator evidence for a
later checkpoint.

No `NSSpeechRecognitionUsageDescription` is added because RT-2c does not run
Apple Speech or any on-device STT API.

## Explicit-user-action rule

RT-2c adds no UI button, startup hook, lifecycle hook, constructor side effect,
or background task that calls the gateway. Therefore:

```text
platform permission request executed: false
microphone opened: false
audio captured: false
raw audio persisted: false
Backend audio upload: false
Framework/provider/STT execution: false
```

RT-2d may add capture lifecycle models/controller and a fake capture engine only
after RT-2c acceptance. Real microphone capture remains blocked until RT-2e.

## Focused tests

The focused Flutter tests use an injected fake driver. They cover:

```text
granted check without permission request
denied explicit request mapping
permanently denied/settings affordance
restricted mapping
limited/provisional fail-closed mapping
web/desktop unsupported short-circuit
MissingPluginException safe conversion
generic failure safe conversion
settings open success/failure
no capture metadata
```

The tests never invoke the real platform plugin implementation.
