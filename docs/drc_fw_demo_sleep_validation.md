# DRC 開発版の睡眠読み取り

## 実機の記録

- A301OP（Android API 34、arm64-v8a）で、Google Health からヘルスコネクトへの同期後に、DRC 開発版で昨夜の睡眠記録を読み取れた。開始・終了時刻はヘルスコネクトの記録と一致した。
- 同期前に、DRC が昨夜の対象記録なしと表示することを確認した。このとき、アドバイスの表示は未確認。
- 睡眠の読み取りを拒否しても、気分とキャラクターを選んで端末内アドバイスを表示できた。
- ヘルスコネクト自体が利用できない環境での動作は未確認。

## 段階2 — AI アドバイスの実機確認

- A301OP（Android API 34）から開発用 FastAPI に接続し、実 AI プロバイダーを使った合成睡眠要約なし・あり（385分）の両方で HTTP 200、本文の端末表示、表情タグの API 検証通過を確認した。応答元のプロバイダーは未特定。Health Connect の実睡眠データは送信していない。
- A301OP から USB の `adb reverse` 経由で開発用 FastAPI に到達し、HTTP 503 の応答時にも端末内アドバイスが残り、再試行の案内が表示された。

## 段階3 — ミナの表情と音声再生の実機確認

A301OP（Android API 34、arm64-v8a）で確認した。

- 固定アドバイスを表示すると、ミナの表情が 🙂 から 😌 に切り替わった。自動再生はなかった。
- ローカルで生成したテスト用 MP3 は「再生」を押すと鳴った。再生中に「停止」を押す、気分を変更する、ミナからソラに変更する、固定アドバイスを再表示する、の4操作で途中停止した。
- DRC Backend の `elevenlabs_mina` モードで固定アドバイスを受理し、ElevenLabs の音声合成が1回成功した。
- POST は HTTP 200、`request_state=generated`、`accepted=true`、`audio_ready=true`。後続 GET は HTTP 200、`audio/mpeg` で、A301OP で音声が流れた。
- ミナ用音色の聞き取りと、実音声の途中停止は未確認。テスト用 MP3 では上記4操作での途中停止を確認済み。
- 以前の `elevenlabs_mina` モードでの再生失敗の原因は未特定。FW v6.0.0 のソース・設定・依存バージョンは変更していない。

### AI 生成アドバイスの実機確認

- A301OP でミナの AI アドバイスを生成し、生成後に「再生」を押して端末から音声が流れることを確認した。
- 前回 HTTP 503 が返った `POST /debug/mina/ai-advice` は、段階2で動作した AI・FW 設定と ElevenLabs 設定を同じ FastAPI プロセスに渡した構成で成功した。
- 生成本文と読み上げの完全一致、ミナ用音色の聞き取り、実音声の途中停止、生成アドバイス表示時の実機での表情切り替えは、個別の確認報告がなく未確認。

### ソラ・レイの AI 生成アドバイスの実機確認

- A301OP でソラとレイをそれぞれ選び、各キャラクターの生成アドバイス本文が表示され、選択したキャラクターの音色で読み上げられることを確認した。
- 生成時の表情切り替えと、音声取得中にキャラクターを変更した場合の古い音声の破棄は、自動テストで確認済み。実機での結果は未報告。

## 開発版の動作

Android 14 以降で「Health Connect から読み込む」を押したときだけ、睡眠の読み取り許可を確認し、必要な場合に許可画面を開く。読み取ったデータはその画面で使う。保存や Backend への送信は行わない。

端末のタイムゾーンで前日18時以降、当日6時より前に始まり、当日0時を過ぎて現在までに終わったセッションが対象。複数あれば最長の1件を表示する。同じ長さなら終了が遅いものを選ぶ。表示する「記録の長さ」はセッションの開始から終了までの経過時間で、睡眠段階による実睡眠時間の集計は行わない。

## 実機確認

`app_public` で次を実行する。開発版のアプリ ID は末尾が `.dev` で、公開ベータと同居できる。

```powershell
flutter run --debug -t lib/main_sleep_debug.dart
```

1. 起動直後に睡眠の許可画面が開かず、気分とキャラクターを選ぶと端末内アドバイスが出る。
2. 読み込みボタンから許可画面を開いて拒否し、拒否の案内と端末内アドバイスを確認する。
3. 読み込みを再試行して許可する。必要であれば端末の Health Connect 設定で許可する。表示された開始・終了時刻を昨夜の対象記録と端末上で照合する。
4. 対象記録のないテスト環境と Health Connect を使えない環境でも、案内を確認して端末内アドバイスまで進める。照合結果と発生した状態を記録する。
